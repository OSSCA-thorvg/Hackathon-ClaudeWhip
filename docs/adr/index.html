Decision Records

  • ADR-0001Two-Tier Architecture: Node Bridge Server + Browser Client

    The Agent SDK is Node-only (subprocess model), so it cannot run directly in the browser → a local bridge server detects sessions and pushes them over WebSocket.

  • ADR-0002Typed Event Bus with a Shared Contract

    Components do not import each other; they share only the shared event contract. Transport abstraction + handler isolation + coalescing + late-joiner cache.

  • ADR-0003Worker Strategy: Rendering on the Main Thread, Game Logic in a Worker

    thorvg webcanvas does not support OffscreenCanvas/worker rendering (confirmed via official issues) → only the simulation is split into a worker, keeping the main thread dedicated to drawing.

  • ADR-0004Active Session Detection: ps Process Scan + Session File mtime + SDK

    A running claude --session-id process is the evidence of activity. jsonl mtime distinguishes working/idle, the SDK enriches metadata. 1-second polling.

  • ADR-0005Rendering Strategy: Canvas per Session + 'sw' Renderer + Lottie Markers (Superseded by 0006)

    One shared WASM module, one Canvas per session. Global 'sw' renderer to avoid the WebGL context cap. State transitions are Lottie marker segments.

  • ADR-0006Single Canvas + Scene per entity + 'gl' Renderer

    Reflects the user's original intent: a single canvas covering the whole game area, with characters placed as Scene nodes. One canvas = the context cap disappears → switch to 'gl'. Labels/HUD are DOM overlays.

  • ADR-0007Server-Optional Client: Manual Connection + Reactive Session Lifecycle

    Static hosting (GitHub Pages) is the premise — there is no auto-connect; the user connects to the bridge address from the top bar. The stage boots with 0 targets and membership is entirely event-driven (pop-in/fade-out). When the connection drops, the targets disappear too.

  • ADR-0008World Space + Deadzone Camera + Viewport Culling

    The coordinate system is promoted from viewport to world (dropping the floor concept) so that all sessions exist even when there are more of them than fit on screen. The camera is a render-only vertical offset that follows only outside a 25% top/bottom deadzone — the simulation and hit detection know nothing about the camera. Off-screen targets are detached from the scene, making per-frame cost proportional to the "visible count" only.

  • ADR-0009Testing Strategy: Pure-Module Units + Fake-Bridge E2E

    Units (Vitest) cover pure modules only, in the node environment; the browser integration layer is covered by E2E (Playwright). Instead of a real server, E2E has a fake bridge WS inject snapshots (framing shares the shared wireFrame) and verifies state through the window.__claudewhip handle — the handle's type is owned by the client, so drift is caught at typecheck. What the tests verify is the contract: expected values are derived from manifest/exported constants, and copying numbers is forbidden.
