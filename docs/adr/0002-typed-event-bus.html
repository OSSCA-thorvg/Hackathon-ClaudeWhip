ADR-0002: Typed Event Bus with a Shared Contract

Accepted · 2026-08-02 · Author: wayfinder charting session

Context — Why this decision is needed

REQUIREMENT calls for separating concerns via event-driven development (EDA). The components are (a) the session monitor adapter, (b) the canvas renderer, and (c) the game logic (worker) — they may live on different threads, so a communication protocol that crosses the postMessage boundary is needed.

Decision — What we decided

Adopt a typed event bus built from the following patterns:

PatternImplementation
Typed event registry (name → payload)EventMap in shared/src/events.ts (compile-time verified)
Components share only the event contract module (importing each other is forbidden)Only @claudewhip/shared is shared — the renderer, worker, and adapter do not know each other
Transport abstractionLocalTransport (same thread) / PortTransport (worker MessagePort) — hidden behind the bus
Handler exception isolation ("do not kill the loop")All handlers wrapped in try/catch
Coalescing options (max wait / max batch)Subscriber-side coalescing — collapses game_state_updated to once per frame
Cached broadcast + late-joiner catch-upcacheId publication + fetchCached() — a character canvas created midway immediately obtains the state
anycast (consumer groups) + coordinatorDeferred — not introduced as long as broadcast alone suffices

Payloads must be structured-clone-able — the postMessage boundary enforces this at the transport layer.

Rationale — Why we did it that way

  • Subscriber-side coalescing is the pattern with the greatest value for canvas rendering — it merges the 60Hz simulation ticks into a single draw, satisfying the optimization requirement
  • REQUIREMENT itself judges that "a manage component may not even be necessary" — broadcast semantics do not need consumer groups, so a coordinator would be speculative complexity

Alternatives — Considered but rejected

  • DOM CustomEvent / EventTarget — Cannot cross the worker boundary and has no type safety
  • External libraries such as RxJS — Overkill for the hackathon scope; keep deps minimal
  • BroadcastChannel alone — Broadcast to all components works, but ack/targeted addressing is impossible; running MessagePort alongside is more flexible

Consequences — Results of this decision

  • Adding a new event = one line in EventMap — publish/subscribe code is type-checked automatically
  • Events are lossy broadcast by default — state recovery is solved with fetchCached rather than delivery guarantees ("delivery is not guaranteed" is an honest contract, not a defect)
  • If work distribution (anycast) becomes necessary, add a coordinator then — this ADR will need to be revised
